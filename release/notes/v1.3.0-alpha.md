# Rift v1.3.0-alpha

Rift now encrypts what it stores about your code, and installs more reliably.

## Install

```sh
# macOS / Linux
curl -fsS https://storage.googleapis.com/rift-e59ea04337d9/v1.3.0-alpha/install.sh | sh
```

```powershell
# Windows PowerShell
irm 'https://storage.googleapis.com/rift-e59ea04337d9/v1.3.0-alpha/install.ps1' | iex
```

Already on v1.2.0-alpha? Run `rift update`.

## What's new

### Encrypted local storage

- **Summaries are encrypted at rest.** The summaries Rift keeps of your files
  are now encrypted with a key per project. The key is stored separately from
  the data, so a copy, backup or sync of Rift's cache can't be read on its own.
  Data from earlier versions keeps working.

### Safer by default

- **Sensitive files are matched regardless of case** on macOS and Windows, so
  `.ENV` is protected just like `.env`.
- **Agent detection ignores relative `PATH` entries,** so a program planted in
  a cloned repository is never run while Rift looks for your agents.
- **Rift no longer writes into the current folder** when it can't find your
  home directory. It tells you what to set instead.

### More reliable installs

- **An interrupted install no longer blocks the next one.** If an install was
  stopped part-way, the next install, update or uninstall picks up cleanly.
- **Windows downloads are size-limited and faster,** and Windows on ARM is
  supported: Windows 11 on ARM runs Rift under emulation, and Windows 10 on
  ARM gets a clear message.

### Easier troubleshooting

- **`rift doctor --report` now includes hook timings** (typical and slowest
  per hook), so performance reports need no extra steps. Like the rest of the
  report, it contains no paths, names or code.

## Supported platforms

macOS 11+ (Apple silicon and Intel), Linux x86-64 and ARM64 with glibc 2.28
or newer, and Windows 10+ x64 (Windows 11 on ARM under emulation). Session
capture supports Claude Code, Codex and Antigravity.

This is an alpha, so expect rough edges. If something goes wrong, run
`rift doctor --report` in the affected project and include its output with
your report.
