# Rift v1.0.0-alpha

Rift helps people understand and manage work done with AI coding tools. It brings
project history, reusable context, and usage information into a dashboard that
runs in your terminal.

This first alpha is for developers, teams, and people commissioning software who
want a clearer view of how AI-assisted work progresses. Day-to-day use currently
requires a terminal and a Git project; people reviewing a team's work can use the
recorded history and usage information to support that review.

## What Rift Does Today

### Keep a Record of AI-Assisted Work

Rift captures supported agent sessions, including prompts, tool activity, file
changes, checkpoints, and usage information where the coding tool provides it.
Checkpoints preserve a Git-backed history that can be inspected later, helping
you understand what happened across sessions.

Captured records are append-only: corrections add to the history rather than
silently replacing earlier records. Integrity checks help identify changes to
that history.

### Carry Useful Context Between Sessions

Total Recall helps supported agents retrieve relevant project context from
recorded work. It tracks what has changed and what information remains valid,
so agents can receive focused context and avoid some repeated reading.

The benefit depends on the project, coding tool, and working session. Rift shows
measured information where available; this alpha makes no fixed savings or
performance guarantee.

### See Project Activity and Usage

Canopy, Rift's terminal dashboard, brings together:

- **Home:** repository status, capture health, and a Recall summary.
- **Models:** information about detected models and integrations.
- **Activity:** recorded agent and project activity.
- **Tokens:** available token usage, context, cost estimates, and savings information.
- **Recall:** read-only inspection of checkpoints, recorded changes, and available session history.
- **Settings:** project capture, Recall, integration, and policy controls.

The dashboard opens on the project where you run `rift`. Its project picker
lets you switch between repositories and their worktrees—separate working
copies of the same repository. Keyboard navigation, mouse controls, and a
command panel provide access to the main workflows.

Usage and cost figures depend on the evidence supplied by each coding tool.
Missing information is shown as unavailable rather than assumed to be zero.

## Getting Started

The installer lets you choose default coding tools for future projects. Every
feature starts on; switch any of them off per project in Project Settings.
In your project folder, run:

```sh
rift
```

For a new project, a terminal wizard guides you through integrations, project
settings, and supported permission choices before opening the dashboard. Review
and confirm the proposed setup before Rift applies it. Existing project policy
takes precedence over installation defaults. Importing historical sessions is a
separate opt-in step.

Useful commands:

- `rift install` — review your installation defaults.
- `rift doctor` — check the current project's configuration and integration health.
- `rift --help` — explore available commands.
- `rift update --from <download-manifest-url>` — update a managed installation using a published release's download manifest.
- `rift uninstall` — remove the managed installation and Rift-owned integrations while retaining captured data by default.

## Supported Coding Tools

Session capture in this alpha supports **Claude Code, Codex, and Antigravity**.
Support varies with the installed tool and its available integration features.
Other integrations may appear in detection results but are not enabled for
capture in this release.

Authentication, permissions, and any approval required by your coding tool remain
explicit user actions. Rift provides setup and diagnostics for supported
integrations.

## Data and Privacy

Rift stores its captured project history locally and uses Git-backed checkpoints.
It applies redaction to captured records before writing them to durable storage.
Keeping raw transcripts is a separate opt-in choice with an explicit warning;
review that choice carefully for sensitive projects.

Repository policy controls capture and Recall behavior. Uninstalling retains
captured data unless you explicitly choose to purge local data; it does not erase
history already recorded in Git.

Review diagnostic output and captured material before sharing them. Project
paths, code, and other sensitive information may still be present. Redaction
supports careful handling of data; it does not replace a team's security review
or information-sharing policy.

## Alpha Availability and Limitations

Rift is an early release. Expect rough edges, incomplete integrations, and changes
as feedback shapes the product. The alpha focuses on the local command-line tool
and terminal dashboard; hosted dashboards and cloud synchronization are outside
this release.

Packages have been built for Intel and ARM64 macOS, x86-64 and ARM64 Linux, and
x64 Windows. Intel macOS has passed native installer and terminal-flow checks.
The remaining four packages await checks on their target systems; public
downloads remain on hold until those checks pass. Installation commands will
accompany the published downloads.

Release archives include SHA-256 checksums. OS publisher signing and macOS
notarization are not included in this alpha. The Linux x86-64 package requires
glibc 2.35 or later; ARM64 requires glibc 2.39 or later. Alpine/musl Linux is
outside the current packaging scope. The Windows x64 package uses a static C
runtime; native Windows installation and terminal behavior remain unverified.

## Feedback

When reporting a problem, include your operating system, terminal, coding tool
and its version, Rift version (`rift --version`), and a short description of what
you expected and what happened. Run `rift doctor` in the affected project for
additional diagnostics, and check its output for sensitive information before
sharing it.
