# Rift v1.3.1-alpha

A maintenance release: more of what Rift stores is encrypted, `rift doctor`
checks your encryption setup, and dependencies are updated for security.

## Install

```sh
# macOS / Linux
curl -fsS https://storage.googleapis.com/rift-e59ea04337d9/v1.3.1-alpha/install.sh | sh
```

```powershell
# Windows PowerShell
irm 'https://storage.googleapis.com/rift-e59ea04337d9/v1.3.1-alpha/install.ps1' | iex
```

Already on v1.2.0-alpha or later? Run `rift update`.

## What's new

### Encryption

- **File outlines are now encrypted too.** The outlines Rift keeps for large
  files use the same per-project key as stored summaries.
- **`rift doctor` checks your project key.** It reports a key file that is
  missing, unreadable or readable by other users, and tells you how to fix it.
- **`rift doctor` finds summaries stored before v1.3.0.** These are still
  unencrypted. Run `rift-memd rebuild` in that project to encrypt them.

### Security updates

- SQLite and the async runtime are updated to versions with current security
  fixes.

### Fixes

- **Linux: crash recovery for session capture now works.** On Linux,
  saving a recovery record failed right after it had succeeded, so an
  interrupted capture could not be picked up later.
- **Windows: `rift worktree status` finds a worktree's activity** however its
  folder path is written, including short (`RUNNER~1`-style) names.
- Rift is now tested on macOS, Linux and Windows on every change, including
  the Windows installer.

## Supported platforms

macOS 11+ (Apple silicon and Intel), Linux x86-64 and ARM64 with glibc 2.28
or newer, and Windows 10+ x64 (Windows 11 on ARM under emulation). Session
capture supports Claude Code, Codex and Antigravity.

This is an alpha, so expect rough edges. If something goes wrong, run
`rift doctor --report` in the affected project and include its output with
your report.
